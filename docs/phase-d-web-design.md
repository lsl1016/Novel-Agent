# Phase D Web 工作台：功能设计与 UI 风格方案

> 状态：产品/设计稿（2026-10-02）。基于总体规划第 13 章 9 工作区定义，落到当前 91 工具运行时的真实能力上。
> 前置：Phase C（一句话开书）的三形态是本工作台"开书向导"的拼图，数据契约已在 `docs/phase-c-product.md` §12 冻结。
> 技术实现方案见 `docs/phase-d-web-tech.md`（BFF/SSE/前端选型/里程碑）。

## 0. 三条产品公理（决定一切功能取舍）

1. **UI 是运行时的视图与操纵面，不是另一套实现**。每个按钮、每张卡片背后必须能指到某个既有 service 方法 / MCP 工具；Web 层零业务规则。
2. **UI 永不绕闸门**。提交闸门（Draft≠Canon）、HITL 决策点、审校 BLOCK——前端只能呈现与发起，不能跳过。"定稿"按钮点下去仍然要过 `chapter_finalize` 的全部前置。
3. **可解释性是产品特性，不是调试功能**。每个 AI 动作可回看它的输入（上下文快照）与输出（审校发现/决策记录）；每个图谱节点可回看证据来源（断言/候选/章节跨度）。

## 1. 全局框架

```text
┌───────────────────────────────────────────────────────────┐
│ 顶栏: 书名切换 ▾ │ [章节时光轴 1‾40 ●] │ 运行状态胶囊 │ ⌘K │
├──────┬────────────────────────────────────────────────────┤
│ 侧栏 │                                                    │
│ 主页 │              工作区主画布                           │
│ 开书 │                                                    │
│ 世界 │         （右抽屉: 实体/发现/决策 详情）              │
│ 叙事 │                                                    │
│ 规划 │                                                    │
│ 写作 │                                                    │
│ 审校 │                                                    │
│ 时间 │                                                    │
│ 运行 │                                                    │
│ 设置 │                                                    │
└──────┴────────────────────────────────────────────────────┘
```

四个全局机制（贯穿所有工作区）：

| 机制 | 说明 |
|---|---|
| **章节时光轴（全局时间游标）** | 顶栏常驻的章号滑杆。拖到第 N 章，全站状态按"截至第 N 章"重渲染：实体属性、关系、信念矩阵、图谱可见性全部回到那一章的世界。双时序系统的 UI 兑现——**世界是可回拨的** |
| **作者模式 / 读者模式** | 登录级开关。读者模式下一切真相值、作者层工具、secret 边全部隐藏（服务端由角色白名单保证，UI 只是呈现）。认知隔离从架构概念变成可体验的产品事实 |
| **全局搜索 + ⌘K 命令面板** | 搜实体/线程/章节/事件/谜团；命令面板直达任何工具动作（"提交第 12 章""恢复运行""晋升候选 #34"） |
| **右抽屉详情模式** | 任何卡片点开都在右抽屉展开完整档案（实体全史/发现上下文/决策记录），不打断当前画布。一切皆深链：`/book/x/entity/hero`、`/book/x/chapter/12` |

## 2. 九大工作区功能设计

### 2.1 项目主页（Project Home）

- **进度环**：已提交章 / 目标章（来自 run 配置与蓝图）；当前篇章带与所在位置。
- **故事压力仪表盘**：未解谜团积压、逾期伏笔、逾期情感债、休眠线程四指针的仪表盘 + 趋势迷你图（`story_pressure_check` / `planning_pressure_check`）。
- **运行状态卡**：运行中/暂停/停止原因 + 最近事件流（`novel_run_status` + 事件表）。
- **待办收件箱**：待决 HITL 决策（author_questions）、待晋升抽取候选、BLOCK 未处理的草稿——三个数字，点进各自工作区。
- **本周写作**：新增章节、字数、修订轮数、token 消耗条形图。

### 2.2 开书向导 / 蓝图（Story Architect）

- **新建书三步向导**（Phase C 的 UI 化）：① 一句话创意输入（+题材/规模/语气/禁忌参数表单）→ ② 访谈聊天面板（≤4 问，每问给选项）→ ③ 一页纸蓝图确认（书名/核心承诺/主角/结局倾向）。
- **开书档案视图**：`bible.md` 的结构化渲染——真相揭示计划表、线程表、篇章表、假设清单（逐条 ✅/❌/改）；"重生成此节"按钮 = stages 局部重生；重生后 **diff 视图**（新增/删除/变更键高亮）。
- **应用与校验**：dry-run 报告页（error 红 / warning 琥珀，人话建议），显式"应用到正典"大按钮 + 二次确认。
- **蓝图编辑器**：字段表单 + 乐观锁版本号显示（并发保护可视化），硬约束清单可编辑。

### 2.3 世界观设定集（World Bible / Entity Graph）

- **双视图**：图谱画布（力导/环形切换，按实体类型着色）↔ 目录表格（筛选/排序/批量操作）。
- **实体档案卡**（右抽屉全屏化）：基本信息、身份档案链（本名/假名/伪装/头衔，Phase A V2 身份子图）、属性时间线（境界/伤势随章变化折线）、关系列表（带起止章与 cause_event 链接）、别名与保密级、叙事链接（参与哪些线/谜团/债）、**证据来源**（confirmed 断言 → 章节 span 可点回正文）。
- **secret 可见性**：默认按当前章节时光轴做可见性过滤；作者模式"开眼"切换显示隐藏边（紫红虚线 + 锁）。
- **三个子图专页**：力量子图（成长史泳道）、器物子图（持有/封印/觉醒沿革链）、地理树（可折叠空间包含树）。
- **抽取收件箱**：Mention 候选列表 → 逐条 晋升/拒绝（带证据链表单）——`Mention→Assertion→Canon` 管线的 UI 闭环。
- **导入/导出**：entity_graph_import 的 dry-run 预览 + diff；全图 JSON 导出。

### 2.4 叙事看板（Narrative Board）

- **泳道视图**：每条叙事线一条泳道，stage 卡片按章节窗口定位在共享章节轴上；窗口到期变琥珀、逾期变红。
- **谜团卡片**：兑付窗口倒计时条（target_min/max 之间绿色安全区）、挂靠线程、关联线索数。
- **伏笔台账**：线索 ↔ 兑付 的**连线视图**（callback_key 配对显式画出来——没连线的悬空线索红色高亮，这就是"显式回收"约束的可视化）。
- **情感债卡片**：类型/强度/创建章/兑现状态；未偿债按强度排序的债墙。
- **信念矩阵**：事实 × 持有者（reader + 各角色）热力图，每格 = 该事实对该持有者在那章的认知状态（不知/怀疑/已知/误信）；点格展开该事实的披露计划（`fact_disclosures_get`）。**三方认知错位一眼可见——这是本产品最核心的一张图**。

### 2.5 篇章/章节规划器（Planner）

- **弧线甘特图**：弧带（色相族区分）、里程碑菱形、线程排期窗、真相揭示旗标（reveal_after）同轴叠加；冲突（窗口越界/揭示早于禁止弧）红叉标注。
- **滚动窗**：Hard/Medium/Soft 三层折叠面板，显示各章规划项与完整度。
- **章节计划卡**：结构化计划 + 内联校验结果（`chapter_plan_check` 的每条规则 ✅/❌）；planner 提问收件箱（author_questions 的选项式作答 UI）。
- **规划压力页**：与主页压力卡联动的完整版。

### 2.6 写作工作室（Writing Studio）

三栏布局，全站唯一的"纸页"场景：

```text
┌──────────┬────────────────────────┬───────────────┐
│ 章节计划   │      正文编辑器（纸页）    │  审校发现       │
│ +安全上下文│   版本v1 v2 v3 ▾ diff    │  BLOCK/WARN   │
│ 摘要      │   草稿‖正典 徽标          │  逐条定位到段落  │
│ token预算条│                        │  一键修订       │
│ 🔒禁知键清单│                        │  定稿检查单     │
└──────────┴────────────────────────┴───────────────┘
```

- **左栏**：本章计划卡片；写作者上下文摘要（token 预算条、收录了哪些实体/线程、`context_explain` 的"为什么收录它"）；**被禁事实键清单**——只显示键名 + 锁图标（不显示值，与服务端一致）。
- **中栏**：纸页质感编辑器（见 §3 排版）；草稿版本页签 + 双栏 diff；外部草稿粘贴入库（`chapter_draft_save source=external`）；"AI 续写/重写此段"光标动作。
- **右栏**：发现列表按严重度分组，点击滚动定位到正文段落；一键 `chapter_auto_revise`（修订循环进度条 v1→v2→v3）；**定稿检查单**：计划有效 ✅ / 审校齐全 ✅ / 该版本 = 被审版本 ✅ → "定稿入正典"按钮点亮（仍走服务端闸门）。

### 2.7 审校中心（Review Center）

- **发现收件箱**：跨章节全部 BLOCK/WARN，按门类（泄漏/连续性/叙事/压力/语义 OOC/文风）与章节双维度过滤；BLOCK 永远置顶。
- **语义审校展示**：发现已脱敏（不出现真相值），附"审校者看到了什么"的说明链接（快照）。
- **修订收敛史**：某章 v1→v3 的发现数曲线，BLOCK 如何逐轮消除——有界自动修订的可视化。
- **全书审计页**：泄漏零记录墙（绿）、每章审校耗时/token、语义审校覆盖率。

### 2.8 时间线 / 事件浏览器（Timeline Explorer）

- **世界时间线**：章节轴为主轴，事件按参与者分泳道；缩放到卷/章/场景三级。
- **因果链视图**：点任一事件，展开 cause_event_id 上溯链与下游后果树（≤16 层防护同步显示）。
- **变迁轨道**：关系变化（建立/结束）、属性变迁（境界进阶阶梯）、器物持有史，全部挂在同一章节轴上对齐。
- **事件创建**（作者模式）：表单带参与者选择、地点、因果父事件——`event_create` 的结构化 UI。

### 2.9 运行中心（Run Center）

- **运行列表**：历史运行 + 状态/章节进度/停止原因。
- **实时监视器**：当前章流水线步进器（计划→草稿→审校→修订→提交，当前阶段呼吸灯）+ 事件流（SSE 推送）+ 每章 token/耗时曲线。
- **配置表单**：目标章、修订轮上限、压力阈值、语义审校开关——SAFE_CONFIG_KEYS 的白名单表单（越界项禁用并提示）。
- **HITL 决策队列**：author_questions 卡片（选项按钮 + 备注框 + 可选配置补丁），提交即 `novel_run_decision_submit`。
- **长跑健康页**：token 平台曲线、泄漏/修订/介入统计——`metrics.py` 的 KPI 面板 UI 化。
- **检查点与回放**：按章查看提交时的上下文快照（`context_snapshot_get`）。

### 2.10 设置（辅助工作区）

模型路由（四角色 base_url/model/max_tokens 状态显示，密钥脱敏）、访问令牌与角色（NOVEL_FACADE_TOKENS 五类白名单管理）、参考图挂载、导出（全书 Markdown/EPUB、架构 JSON、图谱 JSON）、数据备份。

## 3. 整体 UI 风格

### 3.1 风格概念：亮色工房 × 纸页书房（2026-10-02 依用户决策改版）

> 原方案为暗色工房；用户评审后改为**亮色专业风**（Linear/Notion 系：白卡片 + 浅灰蓝底 #f5f6f8 + 柔和投影），语义色系不变、按白底重校对比度（AA），并为每个语义色补 `-bg` 底色变体。纸页书房保留。暗色实现保留为 tokens 快照，后续可做主题切换。

**两种质感，一个系统**：

- **管理面（8 个工作区）= 暗色仪表工房**：数据密集、状态繁多、长时间盯盘。低饱和深石墨底（#15181E 级），信息密度高（14px 紧凑表格、卡片细边框不投影），像专业 IDE / 交易终端 / 剧组控制台。
- **阅读面（写作工作室正文、开书档案、章节阅读）= 暖纸书房**：米白纸底（#F7F3EA 级）、宋体、大行距。中文长篇的阅读与写作场景必须护眼养文气。

切换发生在场景边界（编辑器获得焦点即入纸页），不是两套主题皮肤而是**一个色彩语义系统投射在两种底材上**。

### 3.2 色彩语义系统（状态即颜色，全站统一）

| 语义 | 色相 | 用途 |
|---|---|---|
| 正典 Canon | 琥珀金 | 已提交章节、settled 实体状态、resolved 线程——"定论" |
| 草稿 Draft | 雾蓝 | 未定稿的一切——"暂定" |
| 秘密 Secret | 紫红 + 🔒 | 真相值、隐藏边、作者层读件——永不大面积铺色，只用边/角标 |
| BLOCK / WARN / PASS | 红 / 琥珀 / 绿 | 审校三态，与 traffic light 对齐 |
| 三方认知 | 世界真相紫 / 读者蓝 / 角色青 | 信念矩阵、belief 视图固定三色 |
| 线程状态 | 活跃绿 / 休眠灰蓝 / 已兑付金 | 看板与图谱 |
| 篇章 | 每弧一个色相族 | 甘特带、时间线带、章节轴刻度 |

规则：颜色只表达状态与归属，**绝不做装饰**；同一语义跨工作区同色（泄漏在审校中心是红的，在看板里还是红的）。

### 3.3 字体与排版

- UI：系统黑体栈（-apple-system / HarmonyOS Sans / 思源黑体），14px 基准，数字与 token 计数等宽字体。
- 正文：思源宋体（Noto Serif SC）17-18px，行高 1.9，段距 > 行距，栏宽 ~42em；标题可用楷/宋加大字重。纸页模式下调暗界面边框存在感，让文字成为唯一前景。
- 图谱/看板节点标签 12-13px，但关键状态用色块而非缩小字来传达。

### 3.4 图形语言

- **图谱**：节点形状/角标区分类别（人=圆、势力=方、地点=六边、器物=菱形…）；secret 关系永远虚线+锁；可见性默认跟随章节时光轴。
- **章节轴是一切的脊柱**：时间线、看板、甘特、事件流共用同一条章节数轴刻度语言（每 10 章一个主刻度），用户在任何页面都本能知道"现在是第几章的世界"。
- **连线有语法**：实线=确定关系，虚线=秘密/推断，带箭头弧线=伏笔→兑现回调，粗细=强度（情感债）。
- 动效只做功能性的：流水线步进、时光轴拖动的状态渐变、发现定位滚动；禁止装饰性动画。

### 3.5 品格关键词

一句话概括目标气质：**"考古学家的书房 + 飞行员的座舱"**——读稿时是安静的纸页，管图时是清晰的仪表；处处是锁与灯，处处可回溯证据。不追潮流玻璃拟态，不做通用 SaaS 后台脸。

### 3.6 可用性基线

- 键盘优先：⌘K 全局命令、j/k 列表导航、E 展开抽屉；
- 对比度 AA 以上（暗底状态色全部校验）；
- 读者模式即"剧透安全模式"，可放心投屏分享；
- 破坏性操作（apply 架构、定稿、拒绝候选、重生成）一律二次确认 + 可撤回提示（版本化使然）。

## 4. 前端形态与数据通道（简述）

- 单页应用直连现有 **HTTP facade**（`http_compat.py`），登录 = 角色令牌（复用 NOVEL_FACADE_TOKENS 五类角色），服务端权限即 UI 权限；
- 运行事件用 **SSE** 推送（run events / pipeline 步进），无长轮询；
- 图谱用 canvas 渲染（节点 10²-10³ 量级），时间线/甘特自绘 SVG；
- 编辑器基于 CodeMirror 6 定制（版本 diff、中文排版、段落定位锚点）；
- 纯本地优先：默认 `127.0.0.1` 部署，书籍数据仍在 SQLite，无云依赖。

## 5. 里程碑

| 阶段 | 内容 | 价值主张 | 验收 |
|---|---|---|---|
| **D1 可视先行** | 框架 + 主页 + 运行中心 + 写作工作室（只读为主，编辑器可用） | "长跑看得见"：现在就能盯着无人写作 | 复现 stress 长跑的实时监视；定稿走通闸门 |
| **D2 图谱可视** | 世界观设定集 + 叙事看板 + 时间线浏览器 | "世界翻得动"：实体/信念/因果全部可查可回拨 | 时光轴拖动全站状态重渲染；伏笔连线视图 |
| **D3 创作闭环** | 开书向导（Phase C UI 化）+ 规划器 + 审校中心深化 + 设置/导出 + 多书管理 | "新书开得了"：从创意到第一章全在 UI 内 | 一句话开书在 Web 内走完；抽取收件箱闭环 |

顺序理由：后端已能无人写作，第一批价值是**可观测**；编辑与图谱其次；创作入口最后（依赖 Phase C 契约冻结）。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 图数据量大后画布卡顿 | canvas 分层 + 视口裁剪 + 子图专页分流（力量/器物/地理） |
| 双质感风格失控变成两套产品 | §3.2 语义色系统单一来源（design tokens 文件），底材只换底色不改语义 |
| UI 诱使作者绕过审校直接改正典 | 正典写入动作只在写作工作室的闸门按钮处存在；World Bible 的编辑全部走"作者声明"路径并留 source 标记 |
| 实时事件推送与 SQLite 单写者冲突 | SSE 只读推送；所有写仍经 facade 串行 |
| 范围蔓延成通用 CMS | 三公理兜底：每个功能必须映射到既有工具，否则不做 |
