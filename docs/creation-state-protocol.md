# 创作状态协议 v0.7

> **状态(2026-10-02,V0.11)**:本文的状态机边界仍然有效;正典提交唯一入口 chapter_finalize(v0.8 起),schema 演进见 schema.py 迁移制(至 v6)。


每一章都作为一个创作事务来管理,横跨两个正典知识层:

```text
实体图 / 世界模型
+
叙事图 / 信息模型
```

## 写前上下文

规划器可以获取作者一侧的真相。写作者只能获取来自 `writer_context_get` 的安全包:

- 章节 / 篇章 / 主目标
- 活跃的叙事线
- 未解的谜团
- 未清偿的情感债
- 读者信念
- 视角(POV)角色信念
- 被禁止的世界真相键(不含隐藏值)
- 到期的伏笔 / 排期 / 里程碑
- 近期已提交的章节/事件
- 角色状态
- 面向相关角色、势力、地点、物品、技能、境界、神器等的**可见性过滤后的实体图上下文**

## 章节计划

章节计划(ChapterPlan)可以声明叙事与实体意图:

```json
{
  "primary_goal": "...",
  "entity_keys": ["hero", "north_city", "ancient_sword"],
  "threads": {"advance": [], "maintain": [], "sleep": []},
  "mysteries": {"create": [], "advance": [], "resolve": []},
  "clues": [],
  "reveals": [],
  "payoffs": [],
  "belief_updates": [],
  "events": [],
  "character_states": [],
  "entities": [],
  "entity_aliases": [],
  "entity_attributes": [],
  "entity_relations": [],
  "narrative_entity_links": []
}
```

计划会在正文写作之前完成校验。实体变更会通过同一个章节事务进行检查。

## 知识层

1. **世界真相(作者独有)** — 作者持有的正典真相。
2. **实体图** — 存在什么,以及各实体随时间如何关联。
3. **角色知识** — 每个角色对事实的立场。
4. **读者知识** — 读者对事实的立场。
5. **叙事图** — 谜团、线索、揭示、情感债与叙事线如何暴露/重新诠释世界事实。

机密实体的别名/属性/关系可以绑定到某个 `fact_key`,因此可见性遵循同一套知识状态规则。

## 草稿与审校

草稿带版本且非正典。审校证据绑定到精确的 `(chapter, draft_version)`。

- 确定性连续性审校检查拟议的实体变更;
- 语义审校者可以在内部查看作者一侧的实体图真相;
- 写作者/修订写作者只能看到安全的实体图上下文。

## 提交

`chapter_finalize` 是首选的事务边界:

- 重新校验章节计划;
- 要求提供针对精确草稿版本的审校证据包;
- 拒绝非法知识泄露;
- 提交正文;
- 应用作者声明的叙事图变更;
- 应用作者声明的实体图变更;
- 可选地抽取未声明的候选变更;
- 运行连续性/压力检查;
- 推进规划/运行状态。

自 v0.8 起 `chapter_commit` 不再暴露为工具;正典提交唯一入口是 `chapter_finalize`,提交写入在单个 SQLite 事务中原子完成。
